# 通信復旧と投稿結果の保持（2026-10-18 JST）

## 実装

- APIの応答はContent-TypeとJSONの解析結果を確認する。HTMLのエラーページや切れたJSON、想定外のerrorフィールドをそのまま画面へ出さない。401・403・404・429などのHTTPステータスは保持し、401は引き続きログイン・復旧の入口へ進める。
- 通常のAPI待ちは20秒、投稿添付と足あとの写真のアップロードは120秒で打ち切る。Promise自体にも期限を設け、ネイティブの通信処理がキャンセルを反映しない場合でも画面を待ち続けさせない。サーバー側の処理が取り消せたことは保証しない。
- 書き込みの応答が失われた場合は、保存されている可能性を伝える。自動の書き込み再送はしない。英語・簡体字・繁体字の案内11項目を追加し、翻訳辞書は1,330項目になった。
- 初期接続の再試行はページを再読み込みせず同じセッションで行う。接続を失った後に取得が失敗しても、取得済みの画面と開いている入力を維持する。再接続時の取得は読み取りだけで、保存操作を繰り返さない。
- 複数の一覧取得に順序を付け、遅れた古い応答やエラーで新しい取得結果を巻き戻さない。初期データに必要な主要フィールドがない応答も適用しない。
- 投稿作成の成功応答を受けたら投稿IDを保持する。その後の一覧取得やリアルタイムの移動確認に失敗した場合は、保存済みの案内と「保存済みの投稿を開く」を残す。この操作は一覧取得と移動確認だけで、POSTを再送しない。移動を確認するまで投稿フォームを閉じない。
- ファイル選択後は入力要素をリセットし、添付に失敗した場合でも同じファイルを選び直せるようにする。添付と足あとの写真も共通のエラー処理を使う。
- 320px幅の投稿フォームではグリッドの最小幅を制御し、ダイアログ内の横ずれを防ぐ。

新規ブラウザー検証は各ケースで独立した実サーバーとメモリーDBを使う。通信断はブラウザーのオフライン状態で再現し、HTMLエラー・壊れた応答・遅延した一覧はHTTP境界だけで作る。ユーザー作成、Cookie、投稿、アップロード、閲覧・移動、DBは実装をそのまま実行する。

英語・簡体字・繁体字で、初期接続失敗からの再試行、同じユーザーと文書の保持、オフライン時の入力保持、明示的な再送まで投稿されないことを確認した。ほかに、保存後の一覧取得失敗、HTMLの401でも新しいゲストを作らないこと、同じ画像の再選択、リアルタイム接続前に保存した投稿の回復、古い一覧の遅延到着を検証した。

既存の12件は、主要な3言語操作6件、動画の直接投稿と実再生1件、アカウントと通報運用2件、移動・承認制チャット・保存・管理操作3件。今回、新しい外部動画の実接続・実再生キャンペーンは行っていない。

## 見つけて直した問題

初回の新規9件では7件成功・2件失敗。HTTP通信が戻った直後でもSocket.IOの接続がまだ戻っていないと、投稿保存後にフォームを閉じたのに投稿を開けなかった。移動確認を待ち、失敗時は保存済み投稿の回復操作を残すように修正した。リアルタイム接続を意図的に止めるケースと、古い一覧を遅らせるケースを追加したうえで、関連23件が成功した。

その後の画像確認で、フォームの内部だけが横にずれるケースを見つけた。グリッドの最小幅を直し、文書全体の幅だけでなくダイアログ内部のscrollWidthとscrollLeftも検査するようにして、11件を再確認した。

## 再実行

`walk/` から、ローカルサーバーとChromiumを起動できる環境で実行する。

```sh
npm run typecheck
npm run lint
npm test
npx playwright test tests/e2e/connection-recovery.spec.ts tests/e2e/international.spec.ts tests/e2e/publishing.spec.ts tests/e2e/accounts-release.spec.ts tests/e2e/walk.spec.ts
npm run native:sync
```

Androidはクラウドの保存済みJDK・SDK・Gradle設定で `./android/gradlew -p android --offline --no-daemon --max-workers=1 :app:assembleDebug` を実行した。環境の追加設定・依存追加は不要だった。

## 範囲と残る作業

入力保持は開いている画面のメモリー上のもの。ページの再読み込み、OSによる終了、別端末への復元やオフライン投稿キューは今回の実装ではない。

POSTの成功応答自体が失われて投稿IDを確認できない場合は、保存有無が不明なまま案内する。全APIをサーバー側で冪等化したものではなく、利用者が手動で同じ新規作成を繰り返した場合の重複を全て防ぐ保証はない。自分の投稿・保存状態を確認してから操作する。

実機の通信切替・OSの中断や終了、iOSのコンパイル、ストア署名・提出、本番配置は別途確認する。Dockerイメージは今回再ビルドしていない。配置時は更新したソースからビルドする。動画ライブラリは54本のまま。運営者・対象年齢・サーバー・ドメインなどの未確定事項は [海外向け公開準備](INTERNATIONAL_LAUNCH.md) に残す。
