# 世界・視聴・現実の足あと

## 今回実装したもの

### 不思議な駅と趣味の階層

最初の共通エリアは「不思議な駅」です。キャンバスの扉・洞窟・家・城をクリックするか、地図上の入口ボタンから移動できます。階層表示・「ひとつ戻る」・「駅に戻る」はキーボードやタッチでも操作できます。

駅から発見・音楽・動画・アート・ミーム・ゲーム・アニメの世界へ進みます。ゲーム → RPG → オリジナルRPGの工房、音楽 → 楽器と演奏の家、アニメ → アニメ制作の工房の分岐があります。これは運営が用意した初期の分類で、住人による世界作成は未実装です。作品名の世界は今後分類と運用方針を決めて追加できます。

新規WALK投稿と管理者による編集では、ジャンルに対応した細かい世界を選べます。ジャンルが合わない世界や存在しない世界への投稿はサーバーで拒否します。既存投稿は変更・削除せず、世界未指定なら元のジャンルの入口に表示します。外部URL登録とYouTube収集は現時点ではジャンルの入口に配置します。

場所ごとにオンラインのアバターを分離します。投稿検索から開くと、その投稿の世界へ移動します。個人ルームに配置された投稿はそのルームの配置を使い、配置外の投稿へ進むと投稿本来の世界へ移動します。同じゲストの複数タブでは世界と位置が同期します。世界の移動時には旧世界の閲覧状態を解除します。

マップは菱形の床、建物の側面・屋根・影、奥行きに応じた重なりで2.5Dの箱庭として描画します。人型に加え、ねこ・きつねのアバターを選べます。自由な建築・パーツ制作・外部モデル持ち込みは未実装です。

### 箱庭と一緒に見る・大画面で見る

投稿を開くと地図を操作できる横の視聴パネルが表示されます。スマートフォンでは地図の一部を残す下側パネルになります。「大画面で見る」「箱庭と見る」で切り替えられます。どちらにも現在の閲覧人数、公開に同意した人の名前・アバター・その投稿へのリアクションを表示します。

公開に同意したオンライン閲覧者はキャンバスの投稿前にも集まります。人数は投稿を実際に開いているゲストをサーバーで重複除外して集計し、複数タブを人数に足しません。非公開ユーザーは匿名人数にだけ含まれます。別ルームで同じ投稿を開いている人も、共有に同意しブロックされていなければ視聴パネルの一覧に表示します。地図のオンライン住人は同じ世界に限定します。人数やアバターを架空の利用状況で補いません。

「次の投稿・動画へ」は今いる世界／ルームの投稿から選び、投稿切替・アバター移動・閲覧状態をサーバーで反映します。次へ進む操作は各自の移動です。直接投稿動画には、別に招待・同意付きの [同期視聴](SYNCHRONIZED_WATCHING.md) を追加しました。同期中に次へ進むと離脱します。

### 終了時刻付きの活動中の分身

「足あと・活動」で活動名、運動／勉強／交流の種類、終了日時を設定します。本人による自己申告であり、行動の証明やGPS追跡ではありません。

- 運動の分身はジムルーム、勉強は学校、交流は居酒屋へ配置されます。
- 同時進行は1人1活動。終了時刻は現在から7日以内です。
- ブラウザを閉じてもDB上で終了時刻まで活動が続き、サーバーを再起動しても保持されます。
- 活動中は終了時刻を延長するか途中終了できます。指定時刻で自動終了し、分身が消えて記録が残ります。
- 分身はオンライン住人・実際の投稿閲覧者とは別配列で扱います。オフライン分身をオンライン／閲覧人数へ加算しません。
- 自分の非公開分身は本人だけが見られます。「この活動を共有する」を選ぶと、名前・アバター・活動名・終了時刻・オンラインかどうかを他のゲストにも見せます。メモと写真もその活動の共有対象になります。
- 活動共有はプロフィールの閲覧公開とは別に選択します。ブロックした相手／された相手には分身・共有記録・写真を表示しません。

### 一日の足あと

活動は開始日の記録として保存します。端末のローカル時刻と日付で表示し、日付を選んで以前の記録も見られます。日付をまたぐ活動は開始日の一覧に置きます。

活動名・メモ・共有設定は後から編集できます。終了済みの開始・終了日時も修正できます。終了済み記録の終了時刻を未来へ変更したり、記録編集で活動を再開したりすることはできません。活動中の日時変更は延長・途中終了で行います。競合する複数タブの編集はrevisionで検出して再読み込みを促します。

PNG・JPEG・GIF・WebPの写真を1記録1枚、5MB以内で添付・差し替え・取り外しできます。写真はSQLite内に保存し、公開投稿用の `/media/` に置きません。認証済み本人か、共有された活動を閲覧できるゲストだけが取得できます。共有を取り消すと以後の取得を拒否します。すでに他者が保存した写真まで回収する機能ではありません。

既定は非公開です。プロフィールの「共有された足あとを見る」は共有を選んだ最新100件だけを表示します。閲覧履歴から記録を自動作成することはありません。

## データと更新

マイグレーション `0005.sql` は投稿に任意の `world_id` と、活動記録用の `activities` テーブルを追加します。既存SQLや投稿・ゲスト・保存・会話・個人ルームは消しません。通常の `npm run db:init` またはサーバー起動で未適用分だけ適用されます。`data/` と `.env` は更新時にもそのまま残してください。

DBを削除して初期化しないでください。バージョン更新前のバックアップには停止中コピーかSQLite backup APIを使い、稼働中のWALを取りこぼさないようにしてください。ゲストCookieを失うと既存の記録にアクセスできません。外部認証と復旧機能はまだありません。

## 将来構想との区別

以下は今回の実装に含めていません。

- 招待・同意に基づく同期再生、映画の共同視聴
- 住人が作る趣味世界、建築パーツ、区画権限・復旧、住人承認
- 建築通貨、広告報酬、通貨購入、カジノ、仕事・物品取引
- GPS自動追跡、現実の活動を証明する仕組み
- X/TikTokの自動収集、実YouTube取得の成功確認

全体方針は [PRODUCT_DIRECTION.md](PRODUCT_DIRECTION.md) を参照してください。

続けて見るジャンルを明示的に別ジャンルへ変更すると、そのジャンルの投稿へ進んで対応する世界へ移動できます。「この投稿と同じジャンル」は現在の世界／ルームの中で選びます。

## 今回の検証

Node.js 24.19.0 / Chromium 154 のLinux環境で実施しました。

- 型チェック、lint、ユニットテスト37件、Vite本番ビルド: 成功。
- ブラウザーワークフロー8種類: 複数ゲストと複数タブ、移動と閲覧数、承認・チャット・通報・ブロック、モバイルの移動・保存・非公開設定、管理CRUD、実動画アップロードと再生、個人ルームと外部URL登録、WebRTC音声、階層と視聴モード、活動と記録を各シナリオ内で確認。
- 全8件の通し検証では7件成功、モバイルのタップ検証1件が失敗。新しい入口のあるキャンバスで、読み込み前／画面外の固定座標にタップしていたテストを修正。読み込み完了を待ち、キャンバス内の床をタップする手順でモバイルと階層の2件を再実行し、成功しました。
- WebRTC音声は、既存の `test:e2e:relay` とループバック専用coturnを使って実音声の受信・ミュート・退出を確認しました。今回の一時coturnはDebianの署名検証済みパッケージから展開したものです。通常のローカル環境での直接通信や本番TURN運用とは別の検証です。
- 新規テストで、旧DBの保持、再起動後の活動保持、自動終了、所有権、共有・ブロック・写真のアクセス制御、匿名閲覧者、階層分離、編集競合、ユーザー単位のAPI制限を確認しました。

外部動画提供元の実再生、YouTubeフィードの実取得、本番公開、Windows実行は今回の成功結果に含みません。テストは一時DBを使用し、既存のユーザーデータを初期化しません。
