# ひとりで始める、最初の5分

友達による試用や、友達を連れてくることを前提にしない入口。一人で動画を選び、気に入ったものを自分の窓辺へ持ち帰り、再訪できるようにする。既存の交流・同期視聴は任意の選択として残す。

## 実装する流れ

1. 初回の「ひとりで寄り道を始める」から、名前設定・登録・公開同意をせずに案内を開ける。既存の「まず動画を見てみる」やプロフィール設定からの開始も残す。招待リンクで来た場合は招待の確認を優先し、この入口を重ねない。
2. 駅の「ひとりの寄り道。」、ほかの場所の「ひとりの時間」から、いつでも自分の入口へ戻れる。
3. 「今日の一本を探す」で既存の動画の棚へ。気分・ジャンルは任意のまま。今回、新しい外部動画やSNSからの取得機能を追加したわけではない。
4. 視聴画面の「自分の窓辺に置く」で、保存する動画と置く非公開の部屋を確認。「保存して窓辺で開く」を選んでからお気に入り・配置を保存し、部屋へ移動する。
5. 非公開の部屋がなければ「わたしの窓辺」を用意する。既存の非公開の部屋があれば選べる。公開の部屋は候補に混ぜず、公開設定を自動で変更しない。部屋は一人向けの入口を開いたり動画を見たりしただけでは作らない。
6. 次回も入口に自分の非公開の部屋と、保存した動画を表示する。部屋の再訪で最初に配置された利用可能な動画を開く。再生位置・閲覧履歴の永続保存は今回行わず、開き直して個別視聴する。

部屋から別の動画の棚や、一人でも遊べる既存のゲームへ進める。自分だけが投稿を開いている場合は「いまは、あなたのペースで。」と案内し、他の閲覧者がいる場合は実人数に従って案内する。短編の問いも、一人で思い浮かべる形を含めた文言にする。

ゲストのログインは既存仕様の最大30日。記録を引き継ぐ場合は既存の無料アカウント登録を利用する。別の端末や新しいゲストへ、以前の部屋を自動で渡すことはしない。

## 部屋と閲覧者の公開は別

非公開なのは部屋とその配置。動画そのものは従来の公開投稿であり、投稿を開いている人数は通常どおり数える。本人が閲覧者の公開を許可している場合、その表示は継続する。非公開の部屋へ移動することだけで「誰にも視聴を知られない」と説明しない。

既定のプロフィールの公開はオフのまま。交流の申込みや同期・マイク参加は自動で始めない。同期視聴に参加中の場合は、窓辺への移動で退出する旨を案内し、移動前に退出する。存在しない住人・閲覧者・投稿を補充しない。

## 保存処理

`POST /api/solo/room` に `{postId, roomId?}`。認証済みセッション、通常のCSRF・利用停止・頻度制限が適用される。API本体は `server/solo-room.ts`。

- 動画の棚と同じ対象判定を、最新の正規投稿に対してサーバーで行う。消えた投稿、利用停止者の対象外投稿、設定用サンプル、動画ではない元投稿リンク等は受け付けない。外部動画の実際の再生可否や権利を、形式判定だけで保証しない。
- 指定できるのは自分の非公開の部屋だけ。`roomId` を省略したときは、自分の既存の非公開の部屋を再利用し、なければ一つ作成する。
- お気に入り・必要な部屋の作成・カードの配置は一つのSQLiteトランザクション。失敗時に保存だけ残したり、他の部屋の公開設定を変更したりしない。
- 同じ動画は重複配置しない。同じ操作の再試行で新しい部屋を増やさない。既存の名前・テーマ・説明・装飾・投稿の位置を維持し、新規配置時はリビジョンを進める。古い配置編集からの上書きは既存の409判定で拒否する。
- 部屋は一人5つ、投稿は一部屋40件という既存の上限を守る。満杯のときに別のカードを勝手に削除せず、操作方法を案内する。
- 追加のDB移行は不要。既存のrooms・favoritesを使う。`.env`・data・アップロードを消して初期化する必要はない。

保存処理中に確認画面を閉じた場合、明示した保存は完了することがあるが、遅れた応答で勝手に部屋へ移動しない。再度選べば既存の配置を再利用する。

## 検証の位置付けと今後

独立したユーザーのブラウザ、実際のMP4、実Fastify・SQLiteを使って動作を検証する。スマホ幅のブラウザ検証はiOS・Android実機の確認とは別。自動テストが通ったことは、人が満足したことや海外市場の需要を確認したことを意味しない。今回も友達の紹介や試用をユーザーに依頼しない。

コンテンツの継続拡充、初見の使いやすさの人による評価、海外向け翻訳・市場検証、公開HTTPS・両OS実機・ストア公開は別工程。外部募集・連絡・広告出稿は行わない。
