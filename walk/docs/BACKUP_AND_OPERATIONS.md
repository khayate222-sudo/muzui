# バックアップと復元

バックアップには非公開の足あと写真、メッセージ、認証情報のハッシュ等を含みます。DBも添付ファイルも非公開の運営用ストレージに保管してください。自動で外部サービスへ送信しません。`.env`、管理者キー、署名キーはバックアップやGitへ入れず、別の安全な場所で管理します。

## 作成と検証

WALKフォルダーで実行します。既存のDBがあることが前提です。

```sh
npm run backup:create -- --output /private/storage/walk-backup-new
npm run backup:verify -- --source /private/storage/walk-backup-new
```

保存先は存在しない新しいフォルダーを指定します。既存の保存先は上書きしません。省略時は`walk/backups/`の新しい日時フォルダーです。`backups/`はGit対象外です。

SQLiteのオンラインバックアップ機能で整合したDBを作り、そのDBにある`media_uploads`の添付ファイルを組み合わせて保存します。活動写真はDB内です。ファイルごとのSHA-256・サイズを記録し、SQLiteの整合性・外部キー・添付の対応も検証します。フォルダーは0700、ファイルは0600で作成します。チェックサムは破損検出で、暗号化や第三者に対する署名ではありません。

バックアップ中に投稿の削除等で必要なファイルがなくなった場合は、成功扱いのフォルダーを残さず失敗します。その場合は再実行するか、一時的に書き込みを止めてから実行してください。長期間の稼働・ストレージ容量に応じた監視と世代管理、保管時の暗号化・アクセス制御は運営環境で整えます。

## 新しい場所へ復元

```sh
npm run backup:restore -- --source /private/storage/walk-backup-new --target /private/storage/walk-restored-new
```

破損・一覧不一致・既存の保存先は拒否します。新しいフォルダーに`walk.sqlite`と`uploads/`を作り、元の`data/`や`.env`を変更しません。復元先の確認後に、運営者がサーバーを止めて接続先を切り替えます。自動切替や既存データの削除はしません。

本番で使う前に別の環境で、アカウントログイン・投稿・足あと写真が復元できるか確認してください。復元したDBにはバックアップ作成時のセッション情報も含まれるため、事故や不正アクセスからの復旧時は、切替前に全セッションを無効化して再ログインさせる運用が必要です。

## Dockerでの実行

2026-10-19以降の更新イメージには `backup.ts`、`check-release.ts`、`release-report.ts` も含む。実際の配備時は同じ更新ソースからビルドする。`/app/data` の永続領域内へ、既存でない新しい保存先を指定する。

```sh
docker compose --env-file /secure/path/walk.env -f compose.production.yaml exec walk npm run backup:create -- --output /app/data/backups/pre-update-001
docker compose --env-file /secure/path/walk.env -f compose.production.yaml exec walk npm run backup:verify -- --source /app/data/backups/pre-update-001
```

上のenvファイルは運営者の実際のものへ置き換え、保存先名は毎回新しくする。コンテナ内だけのバックアップは同じディスク障害への備えにならない。確認後に、アクセス制御・暗号化した別の運営用ストレージへ保管する。利用者への公開フォルダーには置かない。保持期間が未確定のまま古い世代を自動削除しない。

復元時には、バックアップ以降に削除された利用者や投稿を再公開しないための照合も必要。全セッションの失効と合わせて、実際の保持・削除方針に従って確認してから切り替える。

## 提供を始める前に決めるもの

- 定期実行のスケジュール、容量監視、保管先と権限、復元訓練。
- 世代の保管期間と削除手順。アカウント削除後でも過去の非公開バックアップに含まれるデータは、その期間に応じて破棄する。
- 問い合わせと通報の確認担当、停止・解除の記録、障害時の連絡方法。

自動の外部バックアップ、世代削除、外部監視サービスの接続は今回実施していません。実際の運用方針と一致するプライバシー文書を公開してから、公開用設定を有効にします。
