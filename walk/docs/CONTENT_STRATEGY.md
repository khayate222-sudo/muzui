# ゲーム・アニメから育てるWALK

2026-10-17追記：URLからのYouTube情報確認と、収集候補の公式プレーヤー・公開先の確認画面を追加した。ジャンルはゲーム・アニメに限らず制作・音楽・日常なども選べる。最新の操作・接続制限は [YOUTUBE_IMPORT.md](YOUTUBE_IMPORT.md)、自動検証は [検証記録](VALIDATION_YOUTUBE_IMPORT_2026-10-17.md)を参照。実YouTubeへの取得・再生は引き続き未確認。

目標は、WALKで作品や感想が投稿され、好きな作品をきっかけに交流する場所になること。初期は外部の公式発信で発見する内容を用意し、直接投稿を並行して増やします。

## 今回の仕組み

- ゲームストリート・アニメガーデンを追加。最初の既存25サンプルを実ユーザーの投稿数に見せかけて増やしません。
- 「WALKに投稿」から文章・画像・短い動画を直接投稿できます。投稿者は現在のゲストプロフィールに結び付き、本人が削除できます。自分の投稿は未保存でも自分のルームへ配置できます。
- 外部投稿には「外部の投稿」、直接投稿には「WALK発」を表示します。「WALK発の投稿」で直接投稿だけを見ることができます。
- 一覧はWALK発を先に、そのほかは実投稿をサンプルより先に表示し、同じ区分では新しい順です。おすすめは保存ジャンル10点・WALK発3点・保存数を合算した簡易順です。人気順はこれまでどおり実際の保存数と現在の閲覧人数です。
- 管理画面からYouTubeチャンネルを登録し、公開Atomフィードの新着を1時間ごとに取得します。APIキーは不要です。既定では公開前の候補として保存し、運営が確認後に公開します。選んだ収集元は今後の新着を自動公開できます。
- 動画は公式プレーヤーで再生し、ファイルを転載しません。チャンネルの動画IDごとに重複除外し、見送ったものや一度削除したものを同じ収集元から復活させません。

## 収集の始め方

1. 管理画面で認証し、「初期コンテンツの収集」へ進みます。
2. 収集元のチャンネルID（`UC`と22文字）、または `https://www.youtube.com/channel/UC…` を入力します。現在は `@チャンネル名`、キーワード検索、ホームのおすすめフィードからの収集には対応していません。
3. 収集元名とジャンルを選びます。最初は自動公開をオフにします。
4. 「今すぐ取得」を押し、「候補を確認」から出典・公式プレーヤー・公開する世界を確認します。確認チェック後に「広場に公開」します。サーバーを起動している間は1時間ごとに新着を確認します。停止中の収集やブラウザだけでの収集は行いません。
5. 継続して扱いたい収集元は「自動公開をオン」に切り替えます。既に公開前の候補に入っているものは手動判断を残し、切り替え後の新着から自動公開します。

チャンネルは運営が選びます。実際に取得・確認していないチャンネルIDを初期データに混ぜたり、収集成功として表示したりしません。まずゲーム会社・アニメ作品の公式発信、公開を希望するクリエイターからの提供を中心にする方針です。管理画面には任天堂・ポケモン公式を想定した収集元の候補ボタンを用意しました。これは接続未確認の候補で、ボタンを押すまで収集元に登録されません。登録後も自動公開はオフで、実取得できた際に投稿者と出典を確認してから公開してください。初期のテスト用サンプルに入っている動画URLは収集元には使いません。

## 直接投稿を増やす施策

開始時からゲーム制作日記、ファンの感想、自作イラスト、短いクリップをWALKに投稿できます。制作仲間を招待し、週ごとのお題・自分のルーム展示・パーティでの感想会へつなげる運用を想定しています。お題イベントの自動運営・報酬・外部クリエイターへの自動連絡は実装していません。

直接投稿数、投稿者数、保存される割合、再訪などを実測してから、外部投稿と直接投稿の表示割合を調整します。特定の比率や成長を架空の数字で表示しません。現段階は直接投稿の優先表示と専用一覧までで、実験配信や成長分析のダッシュボードはありません。

## メディアと保存

直接投稿の画像はPNG/JPEG/GIF/WebP、動画はMP4/WebMに対応。1ファイル25MB、1ゲスト合計200MB、直接投稿100件までです。動画変換は行わないため、形式内のコーデックによって再生できない場合があります。`data/uploads/` にファイル、SQLiteに所有者とメタデータを保存します。アップロード途中・未公開のファイルは所有者だけがプレビューできます。公開後は公開投稿として閲覧でき、Rangeリクエストによる動画再生に対応しています。

更新時はSQLiteだけでなく `data/` 全体を保存してください。登録済みゲストのCookieを残す必要もあります。ゲスト認証のため、Cookieを失った際の本人確認・復旧や別端末へのログインはまだありません。長期運営に向けてアカウント機能とストレージ容量の拡張が次の課題です。

## 実取得と現在の制限

このクラウドではYouTubeへの通信がプロキシで403拒否されました。`www.youtube.com` を許可先として環境設定の下書きへ追加しましたが、保存・公開による反映と再確認はまだ必要です。実際のチャンネル新着の取得成功は未確認で、取得処理・候補公開・重複除外のテストには独立したAtomフィードを使用しています。接続失敗は収集元ごとのエラーとして表示します。

公開フィードの形式・公開状態・提供条件が変わると取得できなくなる場合があります。これはジャンル全体の横断検索ではなく、登録したチャンネルの新着収集です。YouTube Data APIによる検索・詳細情報の取得や、X・TikTokの自動収集は未実装です。後者の追加には各公式APIの認証・利用条件・料金を確認します。個別投稿のURL登録は引き続き使えます。
