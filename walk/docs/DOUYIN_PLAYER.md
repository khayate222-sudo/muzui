# 抖音の公式プレーヤー（2026-10-17）

ユーザーが環境を公開した後、抖音・快手の公式開発者資料へ接続できるようになった。抖音の公式資料にある、**権限申請不要の VideoID からの iframe 取得API**を使い、明示的な操作で再生情報を確認してプレーヤーを開く機能を追加した。快手の動画へこの方式を流用しない。

## 操作

1. 「投稿を集める」で抖音の通常URLまたは共有文を貼り、「抖音の再生情報を確認」を押す。確認だけでは公開・保存・動画再生を始めない。
2. 取得できた題名と縦横のサイズ・確認日時を表示する。作者名はこのAPIに含まれないため、元投稿で確認して入力する。短縮リンクから確認できた場合は通常の動画URLへ置き換える。
3. ジャンル・奥の世界を選んで登録する。従来どおり、題名・作者を手入力して出典リンクとして登録することもできる。失敗した確認を成功済みとは表示しない。
4. 投稿画面の「公式プレーヤーを開く」で再生情報を確認し、成功したときだけ抖音のiframeを表示する。自動再生はオフ。再生は提供元の再生ボタンで始める。
5. 「プレーヤーを閉じる」でiframeを取り除く。再確認・元投稿へのリンクも使える。閉じた後の遅い応答でプレーヤーや投稿画面を開き直さない。

通常の動画URLを持つ抖音投稿は動画の棚・動画だけの絞り込み・一人の窓辺の候補に含める。これは公式プレーヤーを提示できる候補であり、各動画の公開状態・地域条件を満たして再生できる保証ではない。未解決の短縮リンクと快手リンクは、引き続き候補に含めない。サンプル設定の投稿も除外する。

## 同期・人数・元サービスの条件

抖音は個別再生で、WALKの同期視聴の対象に加えていない。公式の再生操作・時刻通知を検証したわけではない。WALKが表示する人数は、実際に同じ投稿カードを開いている人数であり、外部動画の再生人数ではない。名前付き表示は既存の公開同意に従う。

確認操作でWALKのサーバーから抖音へ接続し、プレーヤーを開くと端末からも提供元へ接続する。ログイン・年齢・地域・公開設定・広告等は提供元の条件に従う。動画ファイル・外部アカウントのログイン情報を取得せず、広告や提供元の操作を覆わない。商用公開前の契約・提供地域・表示条件の確認は別途必要。

## 実装

- `POST /api/douyin/preview` は認証・CSRF・既存の入力／頻度制限に従う。抖音以外のURL、未知の追加フィールドを拒否する。
- 固定の `https://open.douyin.com/api/douyin/v1/video/get_iframe_by_video?video_id=...` だけへ動画IDを送る。このエンドポイントは確認した公式資料で権限申請不要とされ、APIキーを追加していない。暗号化されたItemID用APIと区別する。
- 共有短縮リンクは、固定の抖音短縮ホストを最大3回まで手動でたどる。HTTPS・ポート・認証情報・移動先ホストを毎回検査し、通常の動画URLが得られた時点でIDを取り出す。動画ページのHTMLは取得しない。外部ホスト・HTTP・循環・プロフィール等への転送は拒否する。
- 確認全体の待ち時間は10秒。JSON本文64KiBまで、リダイレクトを自動追跡しない。利用者ごと毎分12回、同時8件。成功は動画IDごと最大100件・10分間メモリで保持し、同じURLの並行確認をまとめる。失敗は成功としてキャッシュしない。
- HTTP 200でも `err_no` を確認する。`28003004`（提供元の「非公开视频」）はWALKで422になり、プレーヤーを表示しない。上流の例外や資格情報を利用者へ返さない。
- 返されたiframeのHTMLは描画・保存・クライアントへの転送をしない。`src` のホスト・パス・動画IDを確認し、固定の公式URLを組み立てる。`autoplay=0`、参照元はオリジンまで。任意の外部iframeを許可する設定にはしない。
- WebのCSPへ `https://open.douyin.com` だけを追加した。依存・DB移行・端末権限の追加はない。クライアントとバックエンドを同じ版へ更新する必要がある。

## 今回の実接続で確認できたこと

公式資料を通常のChromiumで読み、API仕様・権限不要の記述・エラーコードを確認した。curlからの呼び出しと、WALKの本物のAPI経由の呼び出しは実接続である。一方、公式資料のサンプル動画 `7471252140422401337` はHTTP 200／`err_no=28003004` と返った。WALKも422と案内を返し、再生成功にはしていない。

プレーヤーページ自体のHTML取得は200だったが、それだけで動画の実再生成功とは扱わない。ユーザーは検証用URLを持っていないと回答しており、提出を前提にしない。公開検索でも確認用の動画URLを得られなかった。新しいブラウザの成功経路は検証用の公式応答・iframe境界を使用している。[検証記録](VALIDATION_DOUYIN_PLAYER_2026-10-17.md)を参照。

## 快手は別の連携が必要

公式の「查询视频」で、`/openapi/photo/list`・`/openapi/photo/info` が `user_video_info` を使い、`app_id` とOAuthの `access_token` を必須とすることを確認した。公式ログイン資料でも、開発者登録・アプリ申請・利用者の同意が前提となる。返却例に `play_url` があることだけを、任意の公開動画の収集・第三者アプリでの配信許可とは解釈しない。

今回、環境の設定要件と変数名の有無を確認したが、両社のアプリ識別子・秘密情報・利用者トークンは提供されていない。抖音の今回のAPIには不要。快手のアカウント連携を進める際は、正式なアプリ・権限・公開HTTPSの戻り先・同意と解除・秘密情報の保管を整える必要がある。使わない仮の資格情報や環境変数は追加していない。快手は元投稿へのリンクを維持する。
