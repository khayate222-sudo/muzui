# WALKを公開・ストア配布へ進める手順

2026-10-19。対象は中国本土以外のアジアと英語圏。英語・簡体字・繁体字で提供し、基本無料とする。任意課金は未実装・未有効。中国本土、自由建築、経済・カジノは別工程。ルートの別サイトには配備しない。

## 今すぐ確認できるもの

`walk/` から `npm run release:report` を実行すると、設定状況と人による確認が必要な項目をJSONで取得できる。設定値・鍵・問い合わせ先・通信の例外本文は出力しない。レポートは読み取りだけで、サーバー作成・公開・課金・ストア申請は実行しない。

`configurationReady` は設定形式の確認、`publicEndpointsVerified` は明示的な `--probe` 実行時の限定的な接続確認。実機、審査、内容の権利を自動で確認したとは扱わず、`readyForPublicRelease` はこのレポートだけではtrueにしない。`voice_relay` のconfiguredも接続試験の代わりではない。

## 運営者が確定する情報

| 必要なもの | 決める内容 | 未設定の間にできる作業 |
| --- | --- | --- |
| 対象年齢 | 成人向けか、未成年を含むか。交流・通報・ストアの申告も合わせる | テスト、表示・導線の改善。年齢を勝手に設定しない |
| 運営と窓口 | 実際の運営者名、問い合わせ先、対応担当と時間 | [文書の確認材料](POLICY_REVIEW_PACKET.md)を使って準備 |
| 正式な文書 | 規約・プライバシー、保存・削除方針、確認済みバージョン | 文書の原案・実データの対応確認。未確認のまま承認しない |
| 配備先 | 有料契約の担当、アジアからの遅延、永続ディスク、バックアップ先、ドメイン | Docker成果物・HTTPSプロキシ設定・復元確認 |
| ストア | Apple／Google開発者アカウント、最終アプリID、署名担当 | [掲載文案](STORE_LISTING_DRAFTS.md)、実機の確認項目 |
| コンテンツ | 配信条件・著者・公開許可の確認担当、Douyin／Kuaishou連携のアプリ登録と権限 | 公式リンク・手動確認・権利のある直接投稿で動作確認 |

鍵、パスワード、署名ファイルはチャットやGitに送らず、配備先やストアの安全な設定で管理する。契約・購入・公開・本人名義の申請は運営者が行う。

## 配備と疎通

1. [海外向け配備手順](INTERNATIONAL_LAUNCH.md)に従い、Nodeの単一インスタンス、永続SQLiteと添付、HTTPSとWebSocket転送を用意する。既存のDB、`.env`、アップロード、バックアップを消さない。`deploy/production.env.example` は項目の見本で、実際の設定はGit外へ置く。
2. 実際の運営者と公開文書を確認して設定する。`WALK_PUBLIC_RELEASE=true`、`COOKIE_SECURE=true`、独自の管理者キーを使う。ローカル検証用の架空の運営者・キーを本番へ転用しない。
3. `npm run release:check` と `npm run release:report -- --probe` を実行する。probeは設定された同一HTTPSバックエンドの `/api/health` と `/api/public/legal` だけを確認し、リダイレクト・HTML・不正JSONを成功扱いしない。これはWebSocket、動画、TURNの疎通試験ではない。
4. 実際の公開先で、ゲスト閲覧、登録、ログインと復旧、投稿・画像・動画、通報、本人のデータ取得・削除を確認する。複数の実セッションで移動・匿名閲覧人数・承認・チャットを確認する。友達の参加を必須とせず、運営者のテスト用アカウントでよい。検証用アカウントを本物の利用実績として表示しない。
5. [バックアップ手順](BACKUP_AND_OPERATIONS.md)で別フォルダーへの復元を練習する。停止したサービスを再起動し、同じ投稿とアカウントが残ることを確認する。復元前のセッション失効・削除済み利用者のデータを再公開しない手順も決める。
6. ディスク容量、サービスのヘルス、バックアップ失敗、通報の未対応を監視する。実環境の保存期間と監視先が決まるまで、自動の世代削除や外部への転送を勝手に設定しない。

## iPhone・Androidの実機確認

公開接続先がない開発用APKは、インターネット上のWALKへ接続できる配布版ではない。`VITE_WALK_SERVER_URL` に実際のバックエンドを設定し、`npm run native:release:sync` で配布対象を作る。AndroidはSDK36／JDK21、iOSはmacOS／Xcodeが必要。署名やTeamは運営者のものを設定する。

以下をOS・端末名・OSバージョン・アプリのコミット・回線・日付と共に記録し、未実施を成功扱いしない。

- 初回の3言語選択、名前を後にして動画の棚へ進む、実際の音と映像、縦横・ノッチ・キーボード。
- 自動再生が制限されたときの「タップして再生」、遅い読み込み、通信断、再試行、別の一本、公式サービスのログイン・地域制限。
- 箱庭・大画面・窓辺の切り替えで同じプレーヤーを保持すること。外部プレーヤーの実再生と、WALKのカードを開いている人数を混同しないこと。
- 画面ロック・着信・バックグラウンドで音やマイクを止めること。復帰だけでは同期グループへ自動再参加しないこと。
- 保存した下書き、OS終了後の復元、未公開添付の本人限定アクセス、公開後の回復、ログアウト時の下書き消去。
- 写真・動画選択、マイク許可の拒否・後からの変更、JSONの保存・共有、招待の共有シート。
- 登録と復旧、他端末のログアウト、本人のデータ削除、通報・ブロック。同期のホストと参加者を別のセッションで確認すること。
- 異なる回線からの音声とTURN。現地回線での動画再生。クラウドChromiumの結果だけで対象国・実機の確認を済ませない。

## ストア提出

1. 開発者登録と最終アプリID・署名を整え、Android App BundleとiOS Archiveを作る。debugビルドはストア署名ではない。
2. [掲載文案](STORE_LISTING_DRAFTS.md)を元に、実装と対象年齢に合う説明・スクリーンショット・サポートURL・プライバシーURL・削除URLを準備する。クラウドのブラウザ画像を実機の審査確認と呼ばない。
3. 外部埋め込み、音声、UGC、アカウント・会話・活動と添付を含めてデータ申告を確定する。広告報酬・課金・GPS・映画配信を機能として載せない。
4. 審査担当が使えるテスト用アカウントを用意し、同期はWALK内の対象動画に限ること、外部SNSは公式プレーヤーまたはリンクであることを説明する。アカウント情報をソースや公開資料へ載せない。
5. まずストアの内部／限定テストで実機結果を集め、解決してから運営者が審査・公開へ進める。サーバー疎通やAndroidビルド成功だけで販売開始としない。
