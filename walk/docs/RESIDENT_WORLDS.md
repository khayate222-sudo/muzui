# 大きな入口と、住人が育てる世界

運営が用意する趣味の大枠は、既存の発見・音楽・動画・アート・ミーム・ゲーム・アニメの七つ。駅、活動先、既存の細分類と投稿を残し、新たな固定の細分類は追加しない。

## 今回使えること

趣味の世界で「世界を育てる」→「この先に世界を作る」。名前、紹介、11種類の景観から選び、公開の子世界を作って訪問する。景観は七つの専用風景と、従来の花の庭・木造街・未来街・石造りの隠れ家。生成りの紙、石畳、植物、午後の光と夕暮れ、同じ手描きの住人でつなぐ。

| 趣味の入口 | 描き込んだ風景 |
| --- | --- |
| 発見 | 絵葉書と地球儀、日々の発見を持ち寄る中庭 |
| 音楽 | 楽器の修理工房、ピアノの演奏会場、レコードの家 |
| 動画 | カメラの工房、赤いひさしの小さな映画館、映像編集の家 |
| アート | 陶芸の窓、画材と彫刻、緑に囲まれたアトリエ |
| ミーム | 紙細工と玩具、風見鶏、仮面と小さな印刷工房 |
| ゲーム | 冒険の道具と地図、旗のある工房、木のゲーム盤 |
| アニメ | 桜の枝、空の作画机、絵コンテと絵具の窓 |

風景の中に人や人数、投稿を焼き込まない。閲覧者、投稿、活動中の分身は従来の実データで描画する。七つの風景の建物は共通の輪郭を持ち、屋根・壁・玄関・看板を押せる。

作成した世界は親のジャンルを引き継ぐ。入口、行き先一覧、現在地の階層、戻り道、招待リンク、友達への場所の招待、投稿先の選択に接続する。そこで「WALKに投稿」を開くと、その世界とジャンルを最初から選択する。追加・更新を他のオンライン端末にも通知する。

## 作成者と訪問者の権限

- 運営の既存の趣味の世界、または自分の作った世界の先に追加できる。他人が作った分岐の下には追加できない。駅直下や活動先に趣味の世界は追加できない。
- 名前・紹介・景観を編集できるのは作成者と管理者。親・ジャンル・所有者は編集できない。古い画面からの上書きは拒否する。
- 訪問者は公開世界への入室と、同じジャンルの投稿ができる。世界の所有権によって他人の投稿を編集・削除できるようにはならない。
- 1人30世界、駅を含めて8階層まで。作成は1分6回まで。公開リリース設定では無料アカウント登録が必要。開発モードではゲストも作成でき、登録時に引き継ぐ。
- 空の世界だけ、明示的に確認して削除できる。投稿や奥の世界がある場合は拒否する。削除した場所の滞在者は駅へ戻す。
- 他の住人の世界の案内から、作成者を既存の通報機能で通報できる。作成者を利用停止にすると、その人の分岐を案内・入室対象から外し、滞在者を駅へ戻す。管理者による復帰で分岐を戻せる。別の人の投稿は残り、ジャンルの入口から参照できる。

## 保存・引き継ぎ

SQLiteの移行 `0008.sql` で `user_worlds` を追加する。既存テーブルのデータを削除しない。世界IDはサーバーで発行し、親と景観をサーバーで検証する。カタログはデータベースごとに構築し、共有モジュールの固定リストをサーバーで書き換えない。

自分のデータ取得JSONに作った世界を含める。アカウント削除時は自分の世界と紹介を削除し、他の人がその世界へ投稿したものはジャンルの入口へ移す。世界そのものの削除操作ではこの移動を行わず、空の場合だけ削除できる。既存のデータ・投稿・`.env` を消して初期化する必要はない。

## 今後の機能

趣味の世界の作成は、名前・紹介・用意した景観による公開世界の作成。別機能として、自分の個人ルームでは床・壁・屋根・家具の組み合わせと保存・復元、設計図JSONの入出力、コイン素材を追加した。[建築とゲーム内経済](BUILDING_AND_GAME_ECONOMY.md) を参照。

独自パーツの制作・外部アセットの持ち込み、共有世界の区画権限、住人の承認・投票、複数人での建築管理、非公開の趣味世界、ストア課金は未実装。公共の道や他人の建物を編集する権限を追加していない。現実の仕事・物品売買・換金は対象外。

ストア公開、iOS実機、Android実機、負荷試験は別の検証。クラウド内のlocalhostは公開プレビューではない。
