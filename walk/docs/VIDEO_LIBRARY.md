# 動画を増やす：16本の実再生確認と初期ライブラリ

2026-10-17（日本時間）。ユーザーの「動画を集め、実際に再生できるか確認して最大限増やす」を優先した。

## 今回増えたもの

抖音・快手は引き続き優先するが、公開ページ・検索のアクセス確認や認証条件が収集の制約となった。中国SNSのbilibiliでは公開カテゴリーと公式の外部プレーヤー資料を閲覧できたため、絵・工作・花・手帳・書道を中心に候補を集めた。

**選んだ候補30本中、16本で公式プレーヤーの実動画が進むことを確認し、16本を初期ライブラリへ追加した。** 新規DBの動画棚はWALKの13本＋外部16本＝29本。候補の残り14本は読み込み・待ち時間・通信の問題で未確認のため、初期データへ入れていない。その前の方法確認用のゲームPV1本は、この30本と初期16本に含めない。

「海外の動画」で外部の動画だけを表示できる。「すべて」「WALKの動画」へ戻せる。ジャンルでさらに絞り、選んだ投稿の世界へ移動し、公式プレーヤーを明示的な操作で開く。日本語の紹介題名、元の題名、元の投稿者、実測した長さ、確認日を残す。動画の表紙はジャンルの風景であり、外部動画の実サムネイルを装わない。

## 実再生の意味と現在の制約

16本は、Linuxの通常のChromiumで公式iframeを読み、見えている再生操作をクリックして、映像のデコード・readyState・再生時刻の進行を実測した。4回の観測の間に少なくとも4秒進み、再生時刻が5秒以上・映像サイズが正・エラーなしであることを確認した。模擬プレーヤー・題名取得・HTMLの200だけを成功に数えていない。

これは**内蔵の確認用ページから公式iframeで冒頭を再生した記録**。全編視聴、全端末・地域の再生保証ではない。後からWALKの本物の画面で3本を再確認したところ、同サービスへの接続経路が503になり、3本とも確認できなかった。一時的に接続が戻った際も、WALKの確認では映像の読み込み後に停止状態が続き、再生時刻の進行は確認できなかった。プレーヤーの操作手順を調整した後の実接続確認も、再び503となった。公式プレーヤーの資料ページと同じ動画のURL形式を比較しても503で、別サービスの公式ページやGitHubへの通信は成功した。以前の成功を消さず、その後の失敗も別の記録として残す。

画面では「開発環境で冒頭を確認」と確認日を表示し、現在必ず再生できるとは表示しない。接続が復旧した後、下記のコマンドでWALK内から再確認する必要がある。現在の一覧を「WALK内ですべて実再生できた」とは扱わない。

[実測結果30件とWALK再確認3件のJSON](verification/VIDEO_CHECKS_2026-10-17.json)に、出典・日時・各回の時刻・映像サイズ・成功／未確認・503を残した。外部の再生回数・フォロワー数はWALKの人気や閲覧者として取り込まない。

## 供給元と操作

[bilibili公式の外部プレーヤー資料](https://player.bilibili.com/)を実際に閲覧した。`bvid` または `aid`、`p`、`autoplay` などのパラメーターが説明されている。WALKは検証したBV形式の通常URLだけを受け付け、公式の `https://player.bilibili.com/player.html` へ埋め込む。BV IDと1〜100の回を検証し、`autoplay=0` を指定する。任意のiframe HTMLを受け付けない。

「投稿を集める」から利用者自身もbilibiliの通常URLを追加できる。題名・作者は手入力で、勝手に取得済みとは表示しない。`b23.tv` など未対応の短縮リンクは通常URLを使う。同じ動画の同じ回は重複登録せず、違う回は別投稿として扱う。公開前のログイン、地域制限、提供元の操作や広告を回避しない。

動画ファイルはbilibiliから配信され、WALKへダウンロード・転載しない。画質・ログイン・広告等は提供元の条件に従う。外部動画の同期視聴は追加していない。WALKの人数は同じ投稿カードを開いている人で、外部動画の再生人数とは別である。

## 後から追加・再確認する

```sh
cd walk
npm run build
# 初期ライブラリを、本物のWALKと公式プレーヤーで確認する
npm run videos:verify
# 候補のJSONを指定する場合（1〜50件）
npm run videos:verify -- --input /path/to/candidates.json --output artifacts/check.json
```

候補は `[{"url":"https://www.bilibili.com/video/BV…","title":"確認用の題名","authorName":"元の作者","genre":"art"}]` の形式。抖音の投稿URLも受け付ける。実在しない例示用URLをそのまま使わず、実際に発見したURLで確認する。

検証は一時DBでWALKを起動し、本物の登録・保存・移動・プレーヤー操作を使う。利用中の `data/` は初期化しない。外部の成功応答を注入しない。動画を保存しない。結果と画面を `artifacts/` へ出し、未確認があれば終了コード1にする。429・503を検出したら残りを止め、未実行を成功にしない。コマンドを実行しただけで初期ライブラリを増やしたり、ネットワーク上へ公開したりはしない。

初期データは `shared/curated-videos.ts` としてレビュー可能な形で管理し、実測済みの16件だけを入れた。一度だけ追加し、既存の利用者の同じURLの投稿・作者・配置・お気に入り・運営の選定を上書きせず、削除済みの収録動画を再起動で復活させない。次の追加も、確認記録と内容を見てから行う。

## 今後の優先

1. 503が解消した環境で、WALK内から初期16本を再確認する。
2. 未確認14本を含む公開候補を、待ち時間・提供元の条件に従って再確認する。成功したものだけ追加する。
3. 抖音の公開動画の収集経路を継続確認する。快手の公式APIには登録・`user_video_info`・OAuthが必要で、資格情報未提供の状態で取得できるとは扱わない。

この段階で外部アカウントへの連絡、募集、広告出稿、課金、ストア公開は行っていない。ユーザーへURLや友達の用意を依頼することも前提にしていない。
