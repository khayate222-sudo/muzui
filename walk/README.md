# WALK

**Don't scroll. Explore.** アバターで歩いて投稿を見つけ、同じ「好き」をきっかけに会話する、小さなリアルタイムSNSです。既存のサイトは親ディレクトリにそのまま残しています。WALKの作業・起動ディレクトリはこの `walk/` です。

## 起動

**自分のPCのブラウザから確認する場合は [LOCAL_START.md](LOCAL_START.md) を参照してください。** 以下の `/workspace` と `localhost` は実行環境内のものです。クラウドのURLを自分のPCで直接開けることを意味せず、このオンボーディング環境には外部向けWebプレビュー機能はありません。

Node.js **24以上**、npmを使用します（Linuxで検証済み）。任意で `.env.example` を `.env` にコピーし、公開URL等を設定してください。外部API・有料サービス・メール登録は不要です。

```sh
cd /workspace/muzui/walk
npm ci
npm run db:init
npm run dev
```

ブラウザで `http://localhost:3001` を開きます。開発時は1つのポートでFastify・Vite・Socket.IOを提供します。別デバイスからはサーバーに到達できるホスト名を使い、`APP_ORIGIN` をそのオリジンに一致させてください（未設定の開発環境ではリクエストのHostとの一致を確認します）。ポートを変える場合は `PORT` を変更します。`.env.example` の `localhost` と `127.0.0.1` は異なるオリジンなので混在させないでください。

クラウドタスクは既に隔離されています。既存チェックアウトを利用し、明示的な依頼がなければ追加のGit worktreeは作りません。サーバープロセスはスナップショット復元後に再起動が必要です。

最初に名前・色・外見を選び、公開する情報を確認します。公開は初期状態で**オフ**です。キーボード（WASD / 矢印）、クリック、スマートフォンのタップで歩けます。近くの投稿はEキーまたはボタンで開きます。投稿検索・エリアボタン・目的地ボタンでも移動できます。マップ右下の小地図と拡大縮小を使用できます。移動やポインター操作が難しい場合は「投稿を探す」からすべて閲覧できます。

## 実装

- React / TypeScript / Vite / Tailwind CSSによるレスポンシブUI。Phaser 3のマップ・イラスト・樹木・広場・噴水・アバターは自作です。スマートフォンは画面下ナビゲーションへ切り替えます。
- テキスト・画像・YouTube・外部SNSリンク。検索、保存、リアクション（いいね・ひらめき・共感）、人気順（保存数＋現在閲覧数）、保存ジャンルを用いた簡易おすすめ。管理者が座標を指定できます。
- Node.js / Fastify / ZodでAPI・Socketイベントを検証。Socket.IOで位置と現在開いている人数を同期。移動送信は約10Hzで、サーバーでも頻度と移動速度を制限します。
- SQLite / Drizzle ORMによるゲスト、セッション、投稿、保存、交流申請、会話、ブロック、通報の永続化。DB処理は `server/db.ts` / `schema.ts`、通信・APIは `server/app.ts`、画面は `src/`、共有入力定義は `shared/` にあります。
- サーバー発行のランダムなHttpOnly / SameSite=Strict Cookie。DBにはトークンのSHA-256だけを保存し、有効期限は30日です。クライアント指定のユーザーIDで認証しません。将来の外部認証ではusersとsessionsの発行処理を差し替えます。
- 同じCookieを使う複数タブは、オンライン・投稿閲覧数で同一ゲストとして集計。タブごとの閲覧状態を保持し、最後の閲覧タブが閉じると退出します。切断はSocket.IO検知時に解除します。突然のネットワーク断では検知まで最大約25秒かかります。
- 閲覧人数は**投稿を開いているゲスト数**であり、再生人数ではありません。非公開ゲストも匿名の人数には含みます。公開に同意した人だけが閲覧者一覧と現在の投稿を公開し、共通投稿数・ジャンルは両者同意時のみ返します。閲覧履歴は永続化しません。
- アバター・近くの人・閲覧者一覧からプロフィールを選び、交流リクエスト→相手の承認→チャット。メッセージは最大1,000文字、送信頻度制限・送信IDによる重複除外あり。ブロックは双方の交流・会話・プロフィール表示を停止します。通報は管理者だけに表示します。

## 初期データと動画

初期データはテキスト15件、自作SVG画像5件、YouTube設定用サンプル5件、エリア5種類。オンラインのダミーユーザーはありません。投稿の「サンプル」は実利用者の投稿を装うものではありません。

YouTubeの初期5件は、再生・埋め込み権限を確認していないため、**設定用サンプルと明記して埋め込みを停止**しています。管理者が権利と埋め込み許可を確認した動画URLへ差し替え、サンプル設定を解除すると `youtube-nocookie.com/embed/<id>` の公式iframeを表示します。広告・標準操作・提供元リンクを覆いません。現環境では実動画の再生成功は検証していません。

外部SNSは出典と元投稿リンクを表示します。公式埋め込みを導入していないサービスは非対応と明示します。スクレイピング・非公式API・動画保存は行いません。画像は自作の `/art/*.svg` またはHTTPS URLを管理者が設定します。ユーザー画像アップロードや外部SNS認証はこのMVPには含みません。

## 管理

PC画面左下の管理ボタンを使用します。管理者キーは `ADMIN_KEY` を設定するか、未設定なら初回起動時に `data/admin-key` にランダム生成されます（所有者のみ読み書き可、Git無視対象）。キーはサーバー上で管理者本人が確認し、管理画面へ入力してください。キーをログやチャットに貼らないでください。管理者キーはクライアントビルドに含めません。

投稿の追加・編集・削除、タイプ、投稿者、出典、ジャンル、座標、サンプル状態を管理できます。通報一覧を確認できます。一般ゲストによる管理API操作は拒否します。管理者認証済みのCookieは他者と共有せず、管理用ブラウザを分けてください。

## DB初期化・マイグレーション・バックアップ

`npm run db:init` とサーバー起動は `server/migrations/` の番号付きSQL（0001・0002）を未適用分だけ順番に適用します。初期データ投入は繰り返し実行でき、既存ユーザー・保存・会話を消しません。管理者が投稿をすべて削除した場合も、自動でサンプルを復活させません。今後の変更は既存SQLを書き換えず、番号付きマイグレーションを追加してください。`schema_migrations` が適用状態を管理します。

`DATABASE_PATH` の既定値は `./data/walk.sqlite`。WALを使用します。バックアップは停止中のDBコピー、またはSQLiteのオンラインbackup APIを使用してください。稼働中に `.sqlite` だけをコピーすると未反映WALを取りこぼします。DB削除は全ゲストとデータの削除になるため、初期化手順としては推奨しません。Cookie削除・別端末では別のゲストになり、現MVPにはアカウント復旧手段がありません。

## 検証

```sh
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run build
```

ブラウザテストは既存 `/usr/bin/chromium` を使用します。ない場合は `CHROMIUM_PATH` を設定するか、Playwright公式のブラウザ・システム依存パッケージ導入手順に従ってください。E2Eは独立した一時DBとポート4173で本番ビルドを起動し、実際の2ブラウザ・複数タブ・チャット・管理・モバイルを検証します。結果画像は `artifacts/`、失敗時トレースは `test-results/`、HTMLレポートは `playwright-report/` に出力します。これらはGit管理しません。外部動画の再生成功や本番への公開をこのテストの成功と同一視しないでください。

## 本番起動とDocker

```sh
npm ci
npm run build
npm start
# または
docker compose up --build -d
```

Dockerは非rootユーザーで実行し、`walk-data` ボリュームにSQLiteと生成キーを保存します。`/api/health` をヘルスチェックに使用します。Composeの既定ポートは3001です。本番のドメインに合わせて `APP_ORIGIN=https://your-domain.example`、TLS終端時は `COOKIE_SECURE=true`、管理キーを安全な環境変数として設定してください。HTTPのローカル検証ではSecure Cookieをオフにします。

通常は `npm run docker:build` でもイメージを作成できます。Codexクラウド内では `npm run docker:build -- --cloud` を使用してください。既存のHTTPSプロキシの名前解決と公開CA証明書をビルド時だけ引き継ぎます。一般的な企業プロキシでは `WALK_BUILD_CA` に公開CA証明書のパスを指定できます。TLS・npmのintegrity検証を無効にしません。アプリの管理キーをビルド引数へ渡さず、CAのマウントも最終イメージに残しません。

リバースプロキシでHTTPとWebSocketのUpgradeを同じNodeサーバーへ転送します。永続ディスクを使える単一コンテナ・VM等に配置します。**SQLite＋メモリ上のpresenceのため、現MVPは1プロセスで実行します。** 複数レプリカへの拡張には共有DB・Redis等のSocket.IO adapterと共有presence実装が必要です。既存サイト用の親ディレクトリ `netlify.toml` はWALKには適用しません。静的ホストだけではAPI・チャットは動きません。

この成果物はローカルで起動・検証するもので、本番公開は別の操作です。公開先のURL・クラウド契約・秘密情報は含めていません。詳細は [運用・改善チェックリスト](docs/OPERATIONS.md) を参照してください。
