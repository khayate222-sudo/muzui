# WALK

**動画の棚は54本（WALK制作13本＋bilibili41本）になりました。** 既存16本と新規25本をWALKのスマートフォン画面内で再生確認しました。確認はこの開発環境での冒頭で、全地域・実端末での再生保証ではありません。[収録一覧・実測範囲・補充手順](docs/VIDEO_LIBRARY.md)を参照してください。

英語・簡体字・繁体字の主要画面と、端末言語／明示的な言語選択に対応。中国本土以外のアジア＋英語圏を先行します。[海外向けの実装・公開準備・残作業](docs/INTERNATIONAL_LAUNCH.md)と、本番用 `compose.production.yaml` を追加しました。サーバー・ドメイン・運営者情報・ストア署名はまだ未設定です。

**動画の供給元は、抖音・快手を優先します。** 「投稿を集める」で共有文や投稿URLを好きな世界へ置けます。抖音は公式の再生情報を確認してプレーヤーを開く機能を追加し、快手は元投稿リンクで扱います。外部動画の実再生成功・同期・自動収集は未確認／未対応の範囲が残ります。[現在の対応と公式資料](docs/DOUYIN_PLAYER.md)を参照してください。

**Don't scroll. Explore.** アバターで歩いて投稿を見つけ、同じ「好き」をきっかけに会話する、小さなリアルタイムSNSです。既存のサイトは親ディレクトリにそのまま残しています。WALKの作業・起動ディレクトリはこの `walk/` です。

**友達を連れてこなくても、一人で始められます。** 初回の「ひとりで寄り道を始める」や駅の入口から一本を選び、気に入った動画を保存して自分の非公開の窓辺へ置けます。次回も入口から自分の部屋と保存した動画へ戻れます。[ひとりの時間の使い方と保存・公開の範囲](docs/SOLO_TIME.md)を参照してください。

初めての人は **「まず動画を見てみる」** から、好きなジャンルと最初の一本を選べます。駅の動画の棚には七本のオリジナル風景映像（各12秒・音声なし）と実際の動画投稿を並べ、見た後の世界への散歩・友達への招待につなげました。管理者が選定順を変更でき、再生未確認の設定サンプルは棚へ含めません。[使い方・選定と保存の範囲](docs/FIRST_FILM_JOURNEY.md)を参照してください。

**一緒に描く動画3本と小さな物語3本**（各32秒・オリジナルの描画アニメーションと合成音）を追加しました。まだWALKでつながっていない友達も、ホストが同意して作る15分の招待リンクから、交流の申込み・承認・同期への別の同意を経て一緒に見られます。[最初の5分の使い方と範囲](docs/FIRST_FIVE_MINUTES.md)を参照してください。

**YouTubeで見つけた一本を、好きな世界へ。** 「投稿を集める」でURLから題名・投稿者・画像を確認し、ジャンルや奥の世界を選んで登録できます。管理画面の新着候補にも公開前の確認画面を追加しました。実YouTubeへの接続はクラウドの通信制限で未確認です。[操作と実装範囲](docs/YOUTUBE_IMPORT.md)、[検証結果](docs/VALIDATION_YOUTUBE_IMPORT_2026-10-17.md)を参照してください。

駅・広場・趣味の世界を、道と建物が一体になった小さな庭へ更新しました。人物・ねこ・きつねと、行き先一覧や視聴・プロフィールなどの画面も同じ手描きと生成りの色に揃えています。庭の屋根や壁から次の世界へ進め、地図の「箱庭の光」で放課後／夕暮れを選べます。[今回の見た目と範囲](docs/WORLD_GRAPHICS.md)を参照してください。 ロゴ・上部の操作・下部ナビも、駅舎と切符・手帳の線画へ更新しています。[上下のUI](docs/STATION_UI.md)も参照してください。

駅舎・列車・工房・和風の家・未来のパビリオン・洞窟・城を描き込み、建物の屋根や壁もクリック／タップできるようにしました。タップで歩く、ドラッグで見渡す、ピンチで拡大できます。スマホ画面は地図と下部ナビを中心にし、投稿は下から開く視聴パネルで楽しめます。

App Store・Google Play向けのiOS / Androidプロジェクトを追加しています。ブラウザ版は引き続きPCの起動手順で利用できます。ストア版は公開WALKサーバーの設定と実機・署名の検証が必要です。[見た目と操作](docs/MOBILE_AND_VISUALS.md)、[ネイティブアプリの構成と残り](docs/NATIVE_APP.md) を参照してください。

## 起動

自分のルームでは **「窓辺で見る」** を選ぶと、夕暮れの駅を窓から眺める室内で、配置した投稿を実際に視聴できます。部屋・大画面・箱庭を切り替えても同じプレーヤーを使います。窓は静止した背景です。[使い方と今回の範囲](docs/ROOM_WATCHING.md)を参照してください。

**自分のPCのブラウザから確認する場合は [LOCAL_START.md](LOCAL_START.md) を参照してください。** 以下の `/workspace` と `localhost` は実行環境内のものです。クラウドのURLを自分のPCで直接開けることを意味せず、このオンボーディング環境には外部向けWebプレビュー機能はありません。

Node.js **24以上**、npmを使用します（Linuxで検証済み）。任意で `.env.example` を `.env` にコピーし、公開URL等を設定してください。外部API・有料サービス・メール登録は不要です。

```sh
cd /workspace/muzui/walk
npm ci
npm run db:init
npm run dev
```

ブラウザで `http://localhost:3001` を開きます。開発時は1つのポートでFastify・Vite・Socket.IOを提供します。別デバイスからはサーバーに到達できるホスト名を使い、`APP_ORIGIN` をそのオリジンに一致させてください（未設定の開発環境ではリクエストのHostとの一致を確認します）。ポートを変える場合は `PORT` を変更します。`.env.example` の `localhost` と `127.0.0.1` は異なるオリジンなので混在させないでください。

クラウドタスクは既に隔離されています。既存チェックアウトを利用し、明示的な依頼がなければ追加のGit worktreeは作りません。サーバープロセスはスナップショット復元後に再起動が必要です。

最初に名前・色・外見を選び、公開する情報を確認します。公開は初期状態で**オフ**です。キーボード（WASD / 矢印）、クリック、スマートフォンのタップで歩けます。近くの投稿はEキーまたはボタンで開きます。投稿検索・エリアボタン・目的地ボタンでも移動できます。マップ右下の小地図と拡大縮小を使用できます。移動やポインター操作が難しい場合は「投稿を探す」からすべて閲覧できます。

## 実装

- React / TypeScript / Vite / Tailwind CSSによるレスポンシブUI。Phaser 3のマップ・イラスト・樹木・広場・噴水・アバターは自作です。スマートフォンは画面下ナビゲーションへ切り替えます。
- テキスト・画像・YouTube・外部SNSリンク。検索、保存、リアクション（いいね・ひらめき・共感）、人気順（保存数＋現在閲覧数）、保存ジャンルを用いた簡易おすすめ。管理者が座標を指定できます。
- Node.js / Fastify / ZodでAPI・Socketイベントを検証。Socket.IOで位置と現在開いている人数を同期。移動送信は約10Hzで、サーバーでも頻度と移動速度を制限します。
- SQLite / Drizzle ORMによるゲスト、セッション、投稿、保存、交流申請、会話、ブロック、通報の永続化。DB処理は `server/db.ts` / `schema.ts`、通信・APIは `server/app.ts`、画面は `src/`、共有入力定義は `shared/` にあります。
- サーバー発行のランダムなHttpOnly / SameSite=Strict Cookie。DBにはトークンのSHA-256だけを保存し、有効期限は30日です。クライアント指定のユーザーIDで認証しません。将来の外部認証ではusersとsessionsの発行処理を差し替えます。
- 同じCookieを使う複数タブは、オンライン・投稿閲覧数で同一ゲストとして集計。タブごとの閲覧状態を保持し、最後の閲覧タブが閉じると退出します。切断はSocket.IO検知時に解除します。突然のネットワーク断では検知まで最大約25秒かかります。
- 閲覧人数は**投稿を開いているゲスト数**であり、再生人数ではありません。非公開ゲストも匿名の人数には含みます。公開に同意した人だけが閲覧者一覧と現在の投稿を公開し、共通投稿数・ジャンルは両者同意時のみ返します。閲覧履歴は永続化しません。
- アバター・近くの人・閲覧者一覧からプロフィールを選び、交流リクエスト→相手の承認→チャット。メッセージは最大1,000文字、送信頻度制限・送信IDによる重複除外あり。ブロックは双方の交流・会話・プロフィール表示を停止します。通報は管理者だけに表示します。

## 駅から趣味の奥へ・現実の足あと

最初の場所を不思議な駅にし、ゲーム → RPG → オリジナルRPGの工房など、趣味の階層をたどる入口を追加しました。2.5Dの箱庭、ねこ・きつねのアバター、地図と並べる視聴パネル／大画面の切替、公開に同意した実閲覧者の表示を備えます。

「足あと・活動」で終了時刻を自分で設定すると、WALKを閉じてもジムルーム・学校・居酒屋に活動中の分身が残ります。分身はオンライン人数や投稿閲覧人数に含めません。活動記録は既定で非公開。終了・延長、記録修正、メモ・写真、選んだ活動の共有ができます。

操作と制限、実装済み／将来構想の区別は [docs/WORLDS_AND_FOOTPRINTS.md](docs/WORLDS_AND_FOOTPRINTS.md)、引き継ぎ方針は [docs/PRODUCT_DIRECTION.md](docs/PRODUCT_DIRECTION.md) を参照してください。直接投稿動画の同期再生は[招待・同意付きで実装済み](docs/SYNCHRONIZED_WATCHING.md)です。住人による世界作成は[名前・紹介・景観の選択で実装済み](docs/RESIDENT_WORLDS.md)です。自由なパーツ建築、通貨・経済は未実装です。

## 追加した楽しみ方

- 投稿内の「次の投稿・動画へ」で同ジャンルを続けて見る。アバターも投稿前へ移動し、同じワールドの他ユーザーに同期します。動画だけにも絞れます。
- 双方が公開に同意した保存・いいねとジャンルから、プロフィールにマッチ度を表示します。
- 「ルームを探す」で、自分の保存・いいねをドラッグ配置した2Dワールドを作成・公開・訪問できます。
- 「投稿を集める」でYouTube・X・TikTokの実際のURLを登録できます。YouTubeは公式oEmbedの題名・投稿者を確認・編集し、取得できない場合は明示的に手入力できます。X・TikTokは手入力です。YouTubeとTikTokは公式プレーヤー、Xは出典リンクで開きます。
- 「♬ パーティ」で承認済みの友達を招待し、最大6人でWebRTC音声へ参加・ミュート・退出できます。

操作・権限・制限は [docs/COMMUNITY.md](docs/COMMUNITY.md) を参照してください。YouTubeは登録チャンネルの新着収集に対応。X・TikTokの自動収集やDiscordサーバー自動作成は含みません。

## 投稿する場所へ育てる

ゲーム・アニメの2エリアと、WALKへの文章・画像・短い動画の直接投稿を追加しました。画像・動画は既定の `data/uploads/` に保存します。外部投稿とWALK発を区別し、直接投稿を見つけやすくしています。管理画面では指定したYouTubeチャンネルの新着を1時間ごとに候補へ収集し、確認後の公開または新着の自動公開を設定できます。詳細は [コンテンツ方針と操作手順](docs/CONTENT_STRATEGY.md) を参照してください。

このクラウドからの実YouTube取得は通信許可が未反映のため未確認です。チャンネルの登録と通信設定を行う前に、既に外部投稿が自動収集されているとは扱わないでください。

## 初期データと動画

初期データはテキスト15件、自作SVG画像5件、YouTube設定用サンプル5件、エリア7種類。オンラインのダミーユーザーはありません。投稿の「サンプル」は実利用者の投稿を装うものではありません。

YouTubeの初期5件は、再生・埋め込み権限を確認していないため、**設定用サンプルと明記して埋め込みを停止**しています。管理者が権利と埋め込み許可を確認した動画URLへ差し替え、サンプル設定を解除すると `youtube-nocookie.com/embed/<id>` の公式iframeを表示します。広告・標準操作・提供元リンクを覆いません。現環境では実動画の再生成功は検証していません。

外部SNSは出典と元投稿リンクを表示します。TikTokは公式Player v1を表示し、Xは元投稿へ案内します。スクレイピング・非公式API・動画保存は行いません。画像は自作の `/art/*.svg` またはHTTPS URLを管理者が設定します。WALKの直接投稿は画像・動画のアップロードに対応し、外部SNS認証はこのMVPには含みません。

## 管理

PC画面左下の管理ボタンを使用します。管理者キーは `ADMIN_KEY` を設定するか、未設定なら初回起動時に `data/admin-key` にランダム生成されます（所有者のみ読み書き可、Git無視対象）。キーはサーバー上で管理者本人が確認し、管理画面へ入力してください。キーをログやチャットに貼らないでください。管理者キーはクライアントビルドに含めません。

投稿の追加・編集・削除、タイプ、投稿者、出典、ジャンル、座標、サンプル状態を管理できます。通報一覧を確認できます。一般ゲストによる管理API操作は拒否します。管理者認証済みのCookieは他者と共有せず、管理用ブラウザを分けてください。

## DB初期化・マイグレーション・バックアップ

`npm run db:init` とサーバー起動は `server/migrations/` の番号付きSQL（0001〜0005）を未適用分だけ順番に適用します。初期データ投入は繰り返し実行でき、既存ユーザー・保存・会話を消しません。管理者が投稿をすべて削除した場合も、自動でサンプルを復活させません。今後の変更は既存SQLを書き換えず、番号付きマイグレーションを追加してください。`schema_migrations` が適用状態を管理します。

`DATABASE_PATH` の既定値は `./data/walk.sqlite`。WALを使用します。バックアップは停止中のDBコピー、またはSQLiteのオンラインbackup APIを使用してください。稼働中に `.sqlite` だけをコピーすると未反映WALを取りこぼします。DB削除は全ゲストとデータの削除になるため、初期化手順としては推奨しません。Cookie削除・別端末では別のゲストになり、現MVPにはアカウント復旧手段がありません。

## 検証

```sh
npm run typecheck
npm run lint
npm test
npm run test:e2e
# WebRTCの直接UDP通信が制限されている環境では、coturnを導入して
npm run test:e2e:relay
npm run build
```

ブラウザテストは既存 `/usr/bin/chromium` を使用します。ない場合は `CHROMIUM_PATH` を設定するか、Playwright公式のブラウザ・システム依存パッケージ導入手順に従ってください。E2Eは独立した一時DBとポート4173で本番ビルドを起動し、実際の2ブラウザ・複数タブ・チャット・管理・モバイル・ルーム・ワンタップ移動・WebRTC音声を検証します。`test:e2e:relay` はlocalhost専用の一時TURNと一時資格情報を起動して終了時に削除します。`WALK_TEST_TURN_BIN` でturnserverのパス、必要なら `WALK_TEST_TURN_LIB` で共有ライブラリのパスを指定できます。ブラウザの管理ポリシーは変更しません。結果画像は `artifacts/`、失敗時トレースは `test-results/`、HTMLレポートは `playwright-report/` に出力します。これらはGit管理しません。外部動画の再生成功や本番への公開をこのテストの成功と同一視しないでください。

## ローカルの本番ビルドとDocker

以下はローカル確認用です。公開運用には [海外公開手順](docs/INTERNATIONAL_LAUNCH.md) と `compose.production.yaml` を使い、必要な運営設定・HTTPS・永続ディスクを準備してください。

```sh
npm ci
npm run build
npm start
# または
docker compose up --build -d
```

Dockerは非rootユーザーで実行し、`walk-data` ボリュームにSQLiteと生成キーを保存します。`/api/health` をヘルスチェックに使用します。Composeの既定ポートは3001です。本番のドメインに合わせて `APP_ORIGIN=https://your-domain.example`、TLS終端時は `COOKIE_SECURE=true`、管理キーを安全な環境変数として設定してください。HTTPのローカル検証ではSecure Cookieをオフにします。

通常は `npm run docker:build` でもイメージを作成できます。Codexクラウド内では `npm run docker:build -- --cloud` を使用してください。既存のHTTPSプロキシの名前解決と公開CA証明書をビルド時だけ引き継ぎます。一般的な企業プロキシでは `WALK_BUILD_CA` に公開CA証明書のパスを指定できます。TLS・npmのintegrity検証を無効にしません。アプリの管理キーをビルド引数へ渡さず、CAのマウントも最終イメージに残しません。

リバースプロキシでHTTPとWebSocketのUpgradeを同じNodeサーバーへ転送します。永続ディスクを使える単一コンテナ・VM等に配置します。**SQLite＋メモリ上のオンラインpresenceのため、現MVPは1プロセスで実行します。** 複数レプリカへの拡張には共有DB・Redis等のSocket.IO adapterと共有presence実装が必要です。既存サイト用の親ディレクトリ `netlify.toml` はWALKには適用しません。静的ホストだけではAPI・チャットは動きません。

この成果物はローカルで起動・検証するもので、本番公開は別の操作です。公開先のURL・クラウド契約・秘密情報は含めていません。詳細は [運用・改善チェックリスト](docs/OPERATIONS.md) を参照してください。
